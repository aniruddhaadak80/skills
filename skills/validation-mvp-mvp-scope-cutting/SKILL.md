# Cut MVP scope without cutting the point

> Identify the single riskiest assumption and build only what tests it.

**Track:** 🚀 Startup & Founders · **Domain:** Validation & MVP · **Level:** foundation · **~25 min**

**Who this is for:** Founders, Indie Hackers, Early Employees, Solopreneurs

## When to Use This Skill

Identify the single riskiest assumption and build only what tests it.
Use it whenever a matching task appears in conversation — the agent loads these instructions on demand.

## Steps

1. Write the riskiest assumption sentence: 'This works if…'
2. List features; mark each as assumption-tester or decoration
3. Cut decorations ruthlessly for v1 — even obvious-seeming ones
4. Prefer concierge/manual versions over automation initially
5. Define success signal BEFORE launch: threshold, timeframe, metric
6. Timebox build to weeks not months; deadline forces clarity

## Common Pitfalls

- Auth systems built before problem validation
- MVPs so minimal they cannot test the actual hypothesis
